# Qingjian Dictionaries

Ready-to-import dictionaries for the [Qingjian](https://qingjian.app) IME (Chinese input method).

Every dictionary here was generated by AI through the [dictionary-builder skill](#dictionary-builder-skill).
The repository doubles as a **case library**: when building a new domain dictionary, pull an existing one
or mirror its conventions, word-formation patterns and documentation layout.

File naming: `<dictionary>_<version>.tsv` and `<dictionary>_<version>.dict.yaml`, for example
`数学专业术语词库_1万条_2026-10-24-01.tsv`. The version is a date plus a same-day serial, formatted
`YYYY-MM-DD-NN`: the first release of a dictionary on a given day is `01`, a further update that day becomes
`02`, and the serial restarts at `01` on the next day.
Every dictionary ships both files — import either one: `.tsv` is the generic text format, `.dict.yaml` is the
Rime format, whose header `version` field matches the version listed above.
The repository keeps only the **latest** version of each dictionary; earlier versions remain retrievable from
the commit history.

## 2. Installation

1. Clone the repository (Gitee is the primary repo; GitHub is a synced mirror with identical content):

   ```bash
   git clone https://gitee.com/seaworld/qingjian-vocabulary-bank.git

   # or clone from the GitHub mirror
   git clone https://github.com/seaworld92/qingjian-vocabulary-bank.git
   ```

2. In Qingjian: Settings → Dictionaries → Import, then pick the `.tsv` file:

   ![Import location](picqingjian-settings.exe_20261024_011136.png)

3. Restart the IME after importing so the new entries take effect.

## 3. File format

- Three columns per line, tab-separated: `word ⟶ pinyin ⟶ weight`
- Pinyin syllables are **space-separated**, without tone marks; `ü` is always written as `v` (`铝` → `lv`, `率` → `lv`)
- Weights span 800–10039 across five tiers: 7600 / 5200 / 3200 / 1700 / 800. A word always lands in the same tier, so weights are comparable across dictionaries (the mathematics dictionary uses only the four tiers above 1700)
- UTF-8 without BOM, LF line endings

⚠️ **The mechanical dictionary's `.dict.yaml` uses an older convention**: its code column is written as
continuous pinyin (`duihan`). Qingjian decides the dictionary type from the second column — continuous letters
are read as a Wubi dictionary. Prefer the `.tsv` for that dictionary; if you need the YAML, regenerate it with the skill.

## 4. Dictionary builder skill

<https://skillhub.cn/skills/user_7ce48f6f/qingjian-dict-skillhub>

Send this line to your AI agent to install it:

```text
Install @user_7ce48f6f/qingjian-dict-skillhub following https://skillhub.cn/install/skillhub.md
```

The skill produces pinyin dictionaries, Wubi-86 dictionaries, or both. Give it a domain plus a list of parts
or equipment and it expands the word families; it also accepts an existing word list. It handles pinyin and code
assignment, weight tiering, deduplication and sorting, then emits TSV, Rime dict.yaml and a statistics document,
and validates everything against the official Qingjian rules.

Since **1.0.3**, the skill knows about this case library — the agent checks for a comparable dictionary first,
which saves guessing the conventions and building a word list from scratch.
**1.0.4** adds mathematics-specific polyphone rules (奇函数 / 行列式 / 重积分 families plus 着色 zhuo se)
and makes the polyphone examples in the generated documentation project-configurable.
Since **1.0.6**, generated files and the Rime header carry a version number (`YYYY-MM-DD-NN`), the statistics
document states it, and re-running finalize on unchanged content does not create a new version.

## 5. Contributing

Generate a dictionary with the skill, make sure `validate` passes, then drop `<title>_<size>_<version>.tsv` and its
`.dict.yaml` into the repository root, and add a row to both the table above and the changelog below.
Maintainers commit straight to `master`; outside contributors are welcome to open a pull request.
Feature requests are welcome as issues.
